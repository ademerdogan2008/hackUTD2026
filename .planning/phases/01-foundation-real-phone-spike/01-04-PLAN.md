<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone storage -> app | The SpacetimeDB token (bearer credential) is at rest on the device |
| app -> Maincloud | WebSocket over TLS. Reducer args are untrusted from the server's view. |
| Metro logs -> developer terminal | Console output may be shared or screenshotted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-17 | Information disclosure | SpacetimeDB token at rest | mitigate | `expo-secure-store` with `WHEN_UNLOCKED_THIS_DEVICE_ONLY` (no iCloud or other-device backup), key `rp.spacetime_token`. AsyncStorage is grep-gated out. |
| T-01-18 | Information disclosure | Token / secret key in logs | mitigate | Grep gates forbid console lines mentioning the token or secret. The token is never returned from `makeBuilder` handlers. The secret key is zeroed after signing. |
| T-01-19 | Spoofing | Connection target | mitigate | `config.ts` rejects any host that is not `wss://` (TLS). The DB name comes from non-secret config only. |
| T-01-20 | Tampering | Duplicate reducer calls after disconnect | mitigate | No auto-retry of reducer calls. Errors are shown inline. Reconnect is SDK-owned, with no custom timers (grep gate). |
| T-01-21 | Denial of service | Compressed frames on Hermes | mitigate | `.withCompression('none')`, grep-gated. Hermes has no `DecompressionStream`. |
| T-01-22 | Elevation | Ephemeral key misuse | accept | The spike key is per-tap, never persisted, and grants nothing. Phase 2 introduces persisted device keys with signed sessions. |
</threat_model>
