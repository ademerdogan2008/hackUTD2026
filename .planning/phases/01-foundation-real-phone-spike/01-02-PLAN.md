<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any client -> reducers | Any identity, including anonymous, can call `spike_*` reducers with arbitrary args |
| module -> subscribers | Rows leave the server only through views |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Information disclosure | `spike_row`, `spike_verify_result` | mitigate | Tables are private (no `public: true`). The only exposure is `view` (not `anonymousView`) using the indexed `owner.filter(ctx.sender)` / `owner.find(ctx.sender)`. A grep gate asserts exactly 2 `public: true` lines and no `.iter()`. |
| T-01-05 | Denial of service | `spike_seed` | mitigate | The per-call count must be in 1..500, the per-owner total must be at most 1000 (SenderError), and both are tested. Residual risk: many anonymous identities could each insert 1000 rows. This is accepted for a dev spike; `spike_*` is removed or made inert in Phase 2. |
| T-01-06 | Tampering / Spoofing | `spike_verify` signature check | mitigate | noble `ed25519.verify` behind the total `verifySpikeSignature`. Prefix (domain separation `redphone/v1|spike|`), hex charset, and length checks run before the verify. Input caps throw SenderError. Tampered-message and flipped-sig tests are included. |
| T-01-07 | Tampering | Identity comparison | mitigate | Use `.isEqual`/`.equals` and index lookups only, never `===` on Identity (skill rule). |
| T-01-08 | Elevation | Crypto primitives | mitigate | No `ctx.random`, no `crypto.subtle`, no custom crypto. Noble is cross-checked against RFC 8032 TEST 1. |
</threat_model>
