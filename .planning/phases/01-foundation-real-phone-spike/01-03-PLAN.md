## Phase Goal

**As a** Red Phone developer, **I want to** run a pinned monorepo whose SpacetimeDB module is live on Maincloud and whose Expo Go app syncs live rows and gets on-device Ed25519 signatures verified by that module on a real phone, **so that** every later feature builds on infrastructure already proven on real hardware.

## HARD constraints (user, overrides D-07 login wording)

- The machine's global `~/.config/spacetime/cli.toml` belongs to a DIFFERENT project. It must NOT be read for its token, overwritten, or modified.
- Every authenticated `spacetime` call passes the GLOBAL flag BEFORE the subcommand: `spacetime --config-path .spacetime/cli.toml <subcommand> ...`. Route all such calls through `scripts/rp-spacetime.sh`.
- `.spacetime/` is already in `.gitignore`. Do not edit `.gitignore`.
- The token is NEVER echoed, printed, logged, committed, or copied into agent or MCP config. No `set -x`. Login output goes to `/dev/null`. Never run `login show --token`. Never `cat` `.env` or `.spacetime/cli.toml`.
- `spacetime generate` and `build` need no login and do not use the wrapper.
- Prefix every command with `PATH=/opt/homebrew/opt/node@24/bin:$HOME/.local/bin:$PATH`.
- Do not modify any `package.json` or the lockfile. The `publish:dev` and `publish:demo` scripts already exist from Plan 01.

Verified CLI facts (`--help`, CLI 2.14.1): the global option is `--config-path <config_path>`. `login --token <t>` bypasses the browser. `publish [name] -s/--server -p/--module-path --no-config -y -c/--delete-data[=always|on-conflict|never]`. DB names must match `^[a-z0-9]+(-[a-z0-9]+)*$`. `sql [DB] <QUERY> --anonymous -s --no-config --format json`. `call [DB] <FN> [ARGS...] --anonymous -s --no-config`. `describe [DB] --json -s --anonymous`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user -> orchestrator -> .env | The secret crosses from the user into a file on disk |
| scripts -> spacetime CLI -> Maincloud | Bearer token is used for publish/sql/call over TLS |
| this project -> global CLI config | Another project's credentials live in `~/.config/spacetime/cli.toml` |
| shell output -> logs/agent transcripts | Anything printed may persist in agent context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-09 | Information disclosure | SPACETIME_TOKEN in shell output | mitigate | No `set -x`. Login output goes to `>/dev/null 2>&1`. The wrapper refuses `login` with extra args, which blocks `login show --token`. Verification checks use `grep -c` (counts, not values) and file-based `-f` token matching, never echo. |
| T-01-10 | Information disclosure | Token committed to git | mitigate | `.env` and `.spacetime/` are gitignored (verified with `git check-ignore`). `git ls-files` is empty. History scan with `git log -p --all | grep -F -f tokenfile` finds no match. |
| T-01-11 | Tampering | Global `~/.config/spacetime/cli.toml` (other project) | mitigate | Every authenticated call uses `spacetime --config-path .spacetime/cli.toml` through `scripts/rp-spacetime.sh`. A grep gate forbids bare `spacetime ` calls in scripts. `shasum -a 256 -c` against the Plan 01 baseline runs before and after. |
| T-01-12 | Information disclosure | `.spacetime/cli.toml` at rest | mitigate | `umask 077`, the directory is chmod 700, the file is chmod 600, and it is gitignored. |
