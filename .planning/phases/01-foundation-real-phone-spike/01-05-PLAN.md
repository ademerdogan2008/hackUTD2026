## Phase Goal

**As a** Red Phone developer, **I want to** run a pinned monorepo whose SpacetimeDB module is live on Maincloud and whose Expo Go app syncs live rows and gets on-device Ed25519 signatures verified by that module on a real phone, **so that** every later feature builds on infrastructure already proven on real hardware.

- Prefix every command with `PATH=/opt/homebrew/opt/node@24/bin:$HOME/.local/bin:$PATH`.
- Authenticated spacetime calls go ONLY through `bash scripts/rp-spacetime.sh …`. The isolated `.spacetime/cli.toml` is used, and the global `~/.config/spacetime/cli.toml` is never touched.
- Never print the token. Do not modify any `package.json`, the lockfile, or the bindings.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| phone (Expo Go) -> Maincloud | A real untrusted client over cellular or Wi-Fi |
| dev machine Metro -> phone | The JS bundle is served over LAN or an Expo tunnel |
| developer terminal -> agent transcript | Command output persists in agent context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-23 | Information disclosure | Per-sender view on the live DB | mitigate | The live anonymous `sql` of `my_spike_rows` and `spike_row` must return 0 rows or an error (Task 3). Optional second-phone isolation check (Task 2, step 10). |
| T-01-24 | Information disclosure | Token in transcripts or git | mitigate | The file-based token scan over tracked files and full history. `.env` and `.spacetime/` are untracked. The human runs Metro in their own terminal, so no token-bearing output enters the agent context. |
| T-01-25 | Tampering | Global CLI config (other project) | mitigate | `shasum -a 256 -c .spacetime/global-cli.sha256` in Tasks 1 and 3. Authenticated calls go only through the wrapper. |
| T-01-26 | Tampering | Dev bundle over an Expo tunnel | accept | A development-only bundle with no secrets inside it (the DB name is non-secret config). Judges get Expo Go plus the demo DB in Phase 5. |
</threat_model>
